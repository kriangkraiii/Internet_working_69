1. บทสรุป

ก่อนปรับปรุง เราเตอร์ทั้งสามสาขาใช้รหัสผ่าน console และ enable secret ชุดเดียวกัน ทุกคนที่รู้รหัสเข้าอุปกรณ์ได้เท่ากัน ไม่มีตัวตนรายบุคคล ยกเลิกสิทธิ์ใครคนเดียวไม่ได้ และไม่รู้ว่าใครเข้ามาทำอะไร กลุ่มจึงออกแบบการควบคุมการเข้าถึงระนาบการจัดการ (management plane) ด้วย AAA ใน 3 รูปแบบตามขนาดและบริบทของแต่ละสาขา

  • R1 Branch-A AAA แบบ local ทั้ง console และ vty, vty รับเฉพาะ SSH v2 ผ่าน method list SSH-LOGIN
  • R2 HQ AAA ผ่าน TACACS+ Server (192.168.2.2) สำรองด้วยบัญชี local เมื่อเซิร์ฟเวอร์ไม่ตอบ
  • R3 Branch-C AAA ผ่าน RADIUS Server RAD-SERVER (192.168.3.2) สำรองด้วยบัญชี local

นอกจากขั้นตอนของแลบ กลุ่มได้เพิ่ม (1) IPv6 dual-stack ทุกเครือข่ายพร้อม static route (2) SSH บน vty ของ R2/R3 เพื่อทดสอบการตรวจสอบสิทธิ์ผ่านเซิร์ฟเวอร์จาก PC-B/PC-C (3) ผู้ใช้ที่มีเฉพาะบนเซิร์ฟเวอร์ (netops2, netops3) เพื่อพิสูจน์ว่าเซิร์ฟเวอร์เป็นผู้ตอบจริง และ (4) สถานการณ์ข้อผิดพลาด 3 แบบ ได้แก่ shared key ไม่ตรง ลิงก์ไปเซิร์ฟเวอร์ล่ม และ SSH ถูกปิดบน vty พร้อมขั้นตอนวินิจฉัยและกู้คืน

2. การออกแบบเชิงแนวคิดและสถาปัตยกรรมองค์กร

2.3 แผนการกำหนดแอดเดรส IPv4/IPv6

IPv4 ใช้ตามแลบ ส่วน IPv6 ใช้ prefix สำหรับเอกสาร 2001:db8::/32 (RFC 3849) แบ่งเป็น /64 ต่อเครือข่าย โดยเลข subnet ตรงกับเลขสาขา (LAN 1/2/3) และคู่ router ที่เชื่อมกัน (WAN 12/23) เพื่อให้อ่านแล้วรู้ตำแหน่งทันที router ทุกตัวกำหนด link-local แบบคงที่ fe80::N ตามหมายเลข router และ host ใช้ link-local นี้เป็น gateway

2.4 ขอบเขต routing, switching และ management plane

  • Routing: IPv4 ใช้เส้นทางที่แลบตั้งไว้เดิม IPv6 ใช้ static route เพราะเป็น hub-and-spoke ขนาดเล็กที่มีทางออกทางเดียว R1/R3 ใช้ ::/0 ชี้ R2 และ R2 มี route เฉพาะไป acad:1 และ acad:3
  • Switching: แต่ละสาขาเป็น broadcast domain เดียว ไม่มี VLAN เพิ่ม เพื่อให้จุดสนใจอยู่ที่ AAA
  • Management plane: AAA ควบคุมทั้ง console และ vty ส่วนการสื่อสาร router ↔ AAA server ใช้ IPv4 เพราะ Packet Tracer ผูก Network Configuration ของเซิร์ฟเวอร์กับ IPv4 ของ client (อุปกรณ์จริงกำหนด address ipv6 ได้)

4.2 เหตุผลของการตัดสินใจออกแบบ

  • สร้าง username ก่อน aaa new-model: เมื่อเปิด AAA แล้ว vty จะใช้ method list default ทันที ถ้ายังไม่มีบัญชีจะล็อกตัวเองออก
  • ใส่ local ท้าย method list: IOS ไปลองวิธีถัดไปเฉพาะเมื่อได้ ERROR (ติดต่อไม่ได้/หมดเวลา) ไม่ใช่ FAIL (เซิร์ฟเวอร์ปฏิเสธ) จึงได้ความพร้อมใช้งานโดยไม่เปิดช่องให้เดารหัส local เมื่อเซิร์ฟเวอร์ปกติ
  • Named list SSH-LOGIN บน R1: แยกนโยบาย vty ออกจาก console เพื่อเปลี่ยนเฉพาะ vty ไปใช้เซิร์ฟเวอร์ได้ในอนาคต
  • ผู้ใช้เฉพาะเซิร์ฟเวอร์: บัญชี Admin2/Admin3 มีทั้งสองที่ จึงพิสูจน์ไม่ได้ว่าใครตอบ netops2/netops3 ใช้แยกผลของเซิร์ฟเวอร์ออกจาก fallback
  • Static route สำหรับ IPv6: ทางออกของสาขามีทางเดียว static route จึงคาดเดาได้และไม่มี overhead ของโพรโทคอล routing

7. ข้อจำกัดของการจำลอง

  • Packet Tracer ไม่รองรับ tacacs server รูปแบบใหม่ และ Check Results ให้คะแนนคำสั่ง radius server ไม่ถูกต้อง (แลบระบุไว้เอง)
  • รองรับเฉพาะ hash MD5 สำหรับ secret; อุปกรณ์จริงควรใช้ algorithm-type scrypt
  • คำสั่ง debug บางตัวและพฤติกรรม timeout/fallback อาจต่างจาก IOS จริง กลุ่มจดผลจริงในหัวข้อ 6 และใช้โหมด Simulation ช่วยยืนยัน
  • ไม่มี TLS สำหรับ TACACS+/RADIUS, ไม่มี accounting และไม่มีเซิร์ฟเวอร์สำรอง จึงอธิบายเป็นข้อเสนอแนะแทนการสาธิต
